# 予想1 までの表解析（MRF ↔ Mbek M = 2）

[表解析の方法論](table-analysis.md) を使って、表を r47 から予想1（`p(0,0,p(1,1,0)) ↔ 0^0^2`）まで伸ばした記録。
表は [`data/mrf_mbek2.csv`](../data/mrf_mbek2.csv) の r48〜r126 に入っている（新しく 79 行）。
Google スプレッドシートの表も同じ内容（48〜126 行目、予想2〜4 は 127〜129 行目）。

以下、`E = p(1,0,0)`, `A = p(0,E,0)`, `B = p(0,A,0)`, `A' = p(0,E+1,0)` と書き、A 側は `p(0,0,X)` の `X` だけを書く。

## 0. 結論

* **予想1 は正しい**（表の範囲で確かめられる限り）。予想1 の基本列 `a[1], a[2], a[3]` は r119, r122, r125 に、
  B 側の `b[3], b[4], b[5]` も同じ行に着地し、厳密同期 `k = 2` が成り立つ。予想1 の行を隠しても、
  残りの行から FS 逆算だけ（類推 0 票）で `0^0^2` が復元される。表では「予想1」のラベルを外した。
* 表全体（127 行）で、順序違反 0、全行が標準、FS 閉包の派生対応 196 件に矛盾 0。
* 新しい 79 行のうち、leave-one-out で FS 厳密同期により復元 32 行、FS 交互 3 行、類推のみ 42 行、候補なし 2 行（§3）。

## 1. どう進めたか

1. **節目を決める**：予想1 から r47 まで、両側で基本列の貪欲降下をたどった。A 側は
   `p(1,1,0) → p(1,0,E) → p(1,0,1) → E+E → E+A' → …` と 15 段、B 側は 36 段で、
   通過した項が区間の節目になる。
2. **節目どうしの基本列を両側で並べる**：たとえば `p(1,0,1)[n] = E·n` と `0^0^1^1^0[n] = 0^0^1^(1·n)` が
   同じ形なので、`p(1,0,1) ↔ 0^0^1^1^0` と `E·n ↔ 0^0^1^(1·n)` が読める。
3. **自己相似な区間は写す**：r44〜r47 で始まっていた入れ子（`E+p(0,E,■)`）は、トップレベルの r11〜r43 を
   ■ に写して埋めた（B 側は `0^(0^1^1+V) → 0^0^(1^1+V)`）。
4. **行を足すたびに `tablecheck` で検査する**：順序・標準性・FS 同期・FS 閉包・leave-one-out。
   行は任意の順に足し、`tablecheck --sort` で A 側の順序に並べ替えた。
5. **FS 閉包の派生対応から自然な形のものを行に取り込む**（`E·4`, `p(1,0,1)·2`, `p(1,0,3)` など）。

## 3. 根拠の弱い行

* **r102**（`E+E+p(0,E+E+1,0)`）：r87 を `E → E+E` で写した類推だけが根拠。基本列が表の行に着地しない。
* **r103**：leave-one-out では候補なしだが、r104（`E·3`）の基本列 `[2]` と厳密に一致するので、r104 が正しければ正しい。
* **r95, r96**（`Z` が可算の行）：r3 より下の対応（例えば `p(0,0,p(0,1,0)) ↔ 0^0^1`）に依存する。
  この区間は表に無いので、表の外の知識として使っている。
* **類推のみの 42 行**：r44〜r47 型の「写し」で決めた行。FS では確かめられないが、順序・標準性・FS 閉包と矛盾しない。

## 4. 予想2〜4 について

予想2（`p(0,0,p(1,p(1,0,0),0)) ↔ 0^0^2^1`）は、予想1 を `k = 1` で同期させるので、次の対応が導かれる。

* `p(0,0,p(1,p(0,p(1,1,0),0),0)) ↔ 0^0^2^0^2`
* `p(0,0,p(1,p(0,p(1,p(0,p(1,1,0),0),0),0),0)) ↔ 0^0^2^0^2^0^2`

予想4 も `k = 2` で同期する。予想3 はオフセットが決まらない。続けるなら、予想1 から予想2 までを同じ手順で埋める。
